wxPixGrabber Help

Quick reference for fetching links, downloading images, configuring the crawler and diagnosing problems.

Getting Started

  1. Paste a web page or gallery URL into Source.
  2. Choose Fetch Links or press F1.
  3. Review the links discovered in Results.
  4. Choose Start or press F5 to begin downloading.
  5. Use Pause or Stop while a download is running.
Fetching and downloading are separate steps. Fetch first discovers candidate links; Start launches the worker tasks that follow those links and save valid images.

Local HTML

Open HTML lets you scan a saved HTML/XHTML document from disk instead of a live URL.

Downloading

wxPixGrabber follows discovered links, checks the returned content type and validates images before saving them.

OptionWhat it does
Thumbnail Links onlyPrefers the link surrounding a thumbnail rather than downloading the thumbnail itself.
Minimum ResolutionImages must be larger than the configured width and height before they are saved.
Generated filenamesCreates names such as image0_0.jpg using the task and image indexes.
Unique path nameCreates a folder based on the page title for the current scan.
File already existsChoose whether an existing filename is skipped, overwritten or renamed.

Binary duplicate checking also compares downloaded image data with files already present in the destination folder.

Results

The results view keeps the discovered parent links in their scan order. Expand a parent row to see the image result underneath it.

Saved Ignored Error

  • Name / URL shows the fetched link or downloaded filename.
  • Status shows progress and the final result.
  • Size shows the downloaded file size where available.
  • Type shows the detected image format.

Right-click result items for actions such as opening or copying their associated location.

Settings

Open Scan → Settings to change crawler behaviour. Settings are stored in your PixGrabber user folder and can also be saved as profiles.

SettingPurpose
Maximum ConnectionsControls how many download tasks can be active at once.
TimeoutMaximum network wait used by requests and cancellation handling.
Save PathBase folder used for downloaded images.
Browser CookiesSelects the browser cookie store used for requests.
Image FormatsEnables or disables supported image extensions during discovery.
Search FiltersRestricts discovery to matching hosts or URL fragments.
Notify when finishedShows the completion notification and sound.

Profiles let you keep different sets of crawler settings and switch between them from the Scan menu.

Test Server

The built-in dummy site lets you test wxPixGrabber without relying on a real image host.

  • Press F8 to fetch the dummy site.
  • The local test URL is http://localhost:5000/setup_test.
  • Use Scan → Test Server Options… to choose between 1 and 100 test images.
  • The permanent source images and thumbnails remain under crawler/dummysite.

Clean before test

When enabled, wxPixGrabber removes the dedicated PixGrabber_Dummy_Site download folder immediately before test download tasks begin.

Leave it disabled when you deliberately want existing files to remain so you can test duplicate, skip, overwrite or rename behaviour.

Troubleshooting

A site works in the browser but not in PixGrabber

Check the selected browser cookie source, the page URL and the enabled image formats. Some hosts change their HTML or image delivery behaviour over time.

Nothing is saved

Check the minimum image resolution, destination folder, enabled formats and the result statuses. An image can be discovered successfully but later ignored by validation.

Diagnostic log

The rotating diagnostic log is stored at %USERPROFILE%\pixgrabber\pixgrabber.log on Windows. It records requests, task progress and failures without storing full page HTML or cookie contents.

Local test

If a real site is failing, try the F8 dummy test. If the dummy test succeeds, the basic downloader and local task pipeline are working.

Browser Helper

The local server on port 5000 is also used by the original browser-helper integration.

The helper sends captured link information to:

http://localhost:5000/set-html

wxPixGrabber converts that data into a temporary HTML document and passes it into the normal link-discovery pipeline.

Port 5000 is intentionally kept fixed so the existing /set-html integration remains compatible.
